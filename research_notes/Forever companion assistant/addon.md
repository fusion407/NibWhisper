# Forever addon APIs and RestedXP integration

## Which client and live character data should the addon target?

### Takeaway
Target Forever interface 16001, with defensive feature detection. The local installation provides modern quest, skill, and addon APIs; the Vanilla-specific TOC is not the correct source for identifying the Forever interface.

### Cited Findings
- The installed generic TOC declares interfaces including 16001 and selects mainline embeds for `camelot`. The Vanilla TOC's 11509 declaration belongs to a different supported client. Installed version is v4.11.35. — [Local generic TOC](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/RXPGuides.toc:1>).
- The installed addon identifies `WOW_PROJECT_CAMELOT` as `FOREVER`; source includes a distinct Forever branch. — [Local client detection](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/RXPGuides.lua:205>).
- Forever's generated Blizzard quest API specifies `C_QuestLog.GetAllCompletedQuestIDs()` returning an array of quest IDs; `GetNumQuestLogEntries()` counts entries; `GetInfo(index)` returns quest metadata; `GetQuestObjectives(questID)` returns objective records; `IsQuestFlaggedCompleted(questID)` reports character completion. `QUEST_LOG_UPDATE` and `QUEST_TURNED_IN` support refreshes. — [Blizzard generated API, Forever branch](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/QuestLogDocumentation.lua).
- Local RestedXP itself exports completed IDs using the modern array API and, if absent, the legacy `GetQuestsCompleted()` map keyed by ID. These have different table shapes and must not be iterated identically. — [Local completed quest exporter](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/SettingsPanel.lua:3309>).
- Local quest compatibility maps modern quest info to title, level, suggested group, header/collapse state, frequency, and ID; the legacy equivalent is `GetQuestLogTitle`, whose eighth return is the quest ID. It sets a default 40-quest maximum for Forever, but the companion should use the live count rather than hardcode it. — [Local quest wrapper](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/QuestLog.lua:5>), [Local Forever quest-log limit](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/QuestLog.lua:25>).
- Forever skill APIs use `C_SkillInfo.GetNumSkillLines()` and `GetSkillLineInfo(index)`; the latter returns a record including name, header/collapse state, rank, and maximum rank. `SKILL_LINES_CHANGED` is the refresh event. — [Blizzard skill API, Forever branch](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/SkillInfoDocumentation.lua).
- Local RestedXP checks modern `C_SkillInfo` first and global legacy functions second, supporting a table return and a tuple return. Legacy positions are skill name at 1, rank at 4, maximum rank at 7. — [Local profession reader](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/RXPGuides.lua:409>).
- Forever addon APIs provide addon count, names/info/metadata, loaded state, and load-on-demand loading. `IsAddOnLoaded` returns loaded-or-loading followed by loaded. The API also exposes local addon tables only for addons explicitly opting in via their TOC; do not assume arbitrary access through this route. — [Blizzard addon API, Forever branch](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/AddOnsDocumentation.lua).
- The installed RestedXP reads `C_AddOns` or legacy global addon functions. — [Local addon API aliases](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/SettingsPanel.lua:11>).

### Inferences
- Build a context snapshot at Send time and label its capture time; refresh on quest, skill, level, and zone events. Never represent a pasted snapshot as continuously live.
- Store completed quest IDs separately from currently held quests. A quest absent from the active log is not necessarily uncompleted. If the completion API is missing or fails, mark completion coverage unknown rather than exporting an empty array as authoritative.
- Profession recipes known are not equivalent to profession rank. A rank-only snapshot cannot truthfully claim complete recipe knowledge. Inspect the trade-skill/craft window only when available and identify any omitted data.
- Enumerating skill lines may omit collapsed entries depending on client behavior. Preserve UI state when expanding headers, or label the snapshot partial; don't silently claim all professions are captured.
- Use `pcall` around optional APIs and conservative bounds when copying context, with independent status flags indicating failures or truncation.

### Gaps
- No running game was used, so API availability, secret-value restrictions, objective record shapes on this user's exact running build, and whether completed lists contain every historical/repeatable quest remain unverified.
- The original user identifies Forever, but a running build query was not performed. Interface 16001 is supported by the installed generic addon and corroborated by an independent Forever addon author, not measured from the executable.

## How can the assistant read and communicate with RestedXP?

### Takeaway
The installed RestedXP exposes enough in-process state to capture the active guide, progress, and nearby step instructions without altering its files. Treat this as a version-specific adapter, not a guaranteed stable public API.

### Cited Findings
- `Locale.lua` registers the existing addon table with AceAddon using the folder addon name. Consequently `LibStub("AceAddon-3.0"):GetAddon("RXPGuides", true)` is the correct conditional lookup for the internal object. Wrap the lookup in `pcall`; handle absent libraries/addon. — [AceAddon registration](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/Locale.lua:5>), [Installed AceAddon implementation](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/libs/AceAddon-3.0/AceAddon-3.0.lua>).
- `_G.RXPGuides` is assigned to a distinct registry, `addon.RXPGuides`, rather than the internal addon object. Reading `_G.RXPGuides.currentGuide` is therefore the wrong assumption. — [Registry assignment](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/RXPGuides.lua:223>).
- Internal `addon.currentGuide` receives a processed guide table. Current guide name and group are saved into `RXPCData.currentGuideName` and `RXPCData.currentGuideGroup`. — [LoadGuide processing](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/GuideWindow.lua:1901>), [Saved guide identity](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/GuideWindow.lua:1933>).
- `addon.GetGuideProgress(guide)` returns step number and step ID. It defaults to `addon.currentGuide`, reads keyed `RXPCData.guideProgress`, and falls back to the current saved step. Its nominal read may migrate older progress by calling `SaveGuideProgress`. — [Progress accessor](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/RXPGuides.lua:1438>).
- Saved progress is represented by `RXPCData.currentStep`, `currentStepId`, and keyed entries `{step, stepId}` under `RXPCData.guideProgress[guide.key]`. — [Progress persistence](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/RXPGuides.lua:1420>).
- Processed guides contain `steps`; each step has `elements`. Element `text`, `rawtext`, and `tooltipText` appear in display code. Element `questId` (lowercase d) is used by quest handling. Step and element completion are separate; skipped/text-only elements are treated as satisfied in the completion calculation. — [Step display](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/GuideWindow.lua:2172>), [Quest ID usage](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/RXPGuides.lua:302>), [Completion logic](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/GuideWindow.lua:686>).
- RestedXP emits `RXP_GUIDE_LOADED` and `RXP_STEP_COMPLETE` messages using its internal queued message mechanism. Its `RegisterMessage` wrapper changes normal AceEvent registration bookkeeping; don't assume generic AceEvent unsubscribe semantics. — [Guide message](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/GuideWindow.lua:2134>), [Step message](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/GuideWindow.lua:732>), [Custom registration](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/RXPGuides.lua:86>).
- `addon.SetStep(n)` changes guide progress, and `addon:LoadGuideTable(group,name)` selects another guide. These are mutation methods, not context readers. — [Step mutation](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/GuideWindow.lua:755>), [Guide selection](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/GuideWindow.lua:1815>).

### Inferences
- A minimal adapter should export guide identity, saved step and step ID, nearby processed step elements, relevant quest IDs, completion/skip flags, and an explicit availability/error field. Prefer direct saved progress fields for a strictly read-only snapshot, or document the migration side effect if using the accessor.
- Remove WoW color, texture, atlas, and hyperlink control sequences before sending display text to the model. Bound the number and length of steps. Never recursively serialize the internal object, which contains functions and cyclic references.
- Read adjacent steps only as context. Sticky steps and generated steps mean currentStep alone is not a complete representation of every simultaneously active objective. Export step.active and sticky information when present.
- Make any future guide selection or waypoint controls explicit, validated UI actions. Never run arbitrary model-supplied Lua or dispatch model-supplied function names. A reply can suggest an action without executing it.
- RestedXP is optional: the assistant can still use active quests and completion IDs when RXP is absent. Other addons should be listed by name/version/loaded status; a list alone does not grant knowledge of their private state. Add per-addon adapters deliberately.

### Gaps
- The adapter is grounded in installed v4.11.35 static source. No runtime interaction has been observed. Future RXP releases can rename fields or change progress behavior.
- No claim is made that the guide engine exposes a supported external API contract. Public table visibility and a callable method are not the same as stability guarantees.

## How can ChatGPT replies reach the in-game character and UI?

### Takeaway
An ordinary addon cannot call OpenAI directly. A user-mediated copy/paste exchange is a practical baseline; seamless transport is technically achievable with an external screen reader and preinstalled load-on-demand reply addons, but it has real operating limits and is not Blizzard endorsement.

### Cited Findings
- An existing Forever AI addon documents a colored-pixel outbound strip and a pool of 200 load-on-demand reply addons. Reply files are read when a fresh addon is loaded; exhausted slots require a UI reload. The author's tested Forever builds are 1.60.1.69913 and 1.60.1.69977, TOC 16001. This is primary implementation documentation from its developer, not Blizzard approval. — [wow-ai developer README](https://raw.githubusercontent.com/chelinho139/wow-ai/main/README.md).
- Another Forever companion independently documents the same transport architecture and a manual Copy/Paste option. Its screen reader sees only the top of the game window; reply content is written as data in addon files. The author explicitly says ordinary addons have no network or arbitrary runtime file-read access. — [NeverQuestAlone architecture](https://raw.githubusercontent.com/tommygeoco/neverquestalone/main/HOW-IT-WORKS.md).
- The first project's description says screen capture requires windowed/borderless mode and visible encoded pixels, and that memory reading, injection, and generated input are not used. — [wow-ai README](https://raw.githubusercontent.com/chelinho139/wow-ai/main/README.md).
- Blizzard's addon policy requires readable addon code, prohibits adverse game performance, requires compliance with ToU/EULA, and reserves the right to disable addon functionality. It does not approve any of the third-party transport tricks above. — [Blizzard UI Add-On Development Policy](https://us.forums.blizzard.com/en/wow/t/ui-add-on-development-policy/24534).
- The installed RestedXP minimap integration uses a LibDataBroker data object and LibDBIcon registration; left and right clicks dispatch different UI behavior. Its copy/export flow opens a selectable text popup for a user to copy, which supports the baseline pattern. — [Minimap integration](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/SettingsPanel.lua:3654>), [Selectable export popup](<A:/World of Warcraft/_forever_/Interface/AddOns/RXPGuides/SettingsPanel.lua:3322>).
- The pixel bridge's architecture document reports prelaunch file discovery and caching tests. It uses pure-primary three-bit cells to tolerate gamma, four physical pixels per cell, explicit framing/checksums, and DPI-aware GDI capture. It preinstalls load-on-demand slots, publishes the same snapshot by atomic rename into each slot, and matches reply IDs before accepting data. Reload replenishes slots; it is not an unlimited channel. — [Developer's exact architecture](https://raw.githubusercontent.com/chelinho139/wow-ai/main/docs/ARCHITECTURE.md).

### Inferences
- Baseline transport: the user types in-game, addon creates a context/request packet in a selectable EditBox, user copies it into a local companion page, companion calls OpenAI, user copies a reply packet back, addon parses it strictly as data and displays the reply. This works without injection, screenshots, game-process access, or simulated input. It does require alt-tabbing/copy/paste and is not live streaming.
- Never use `loadstring` or Lua table execution for inbound model output. A constrained data wire format with a version, request ID, text payload, and length checks is sufficient. Bind reply request IDs to outstanding requests so stale/cross-character replies cannot be silently attached.
- Keep the API key in the external companion environment/configuration, never in the addon, exported packets, saved variables, screenshots, browser static bundle, or logs. The addon should display truthful connection status, distinguishing manual bridge from ready/connected AI.
- A custom two-dimensional mascot texture plus ordinary Button/Frame widgets is lower-risk than depending on an unverified creature display ID and PlayerModel camera behavior. A 3D mascot requires actual model/frame verification on Forever. Native client UI textures can provide a fallback minimap icon.
- If seamless chat becomes required, pixel egress and slot loading should be a separately tested optional transport, with a narrow explicit screen-reading scope, remaining-slot status, foreground/occlusion/error handling, and manual fallback. Do not promise unlimited slots or minimized-window operation.
- An original optical protocol can reuse those general mechanics without copying the implementation: header magic/version, session and request identity, part index/count, byte length, payload, checksum. Use at most one pending request and cycle parts until a matching reply is received. At 130 by 80 physical pixels, four-pixel cells hold only about 240 bytes; a complete quest snapshot needs multiple parts. Exporting many completed IDs can dominate latency, so cap packet size and disclose any truncation. Capture should require the intended foreground game window and never persist screenshots.
- For inbound slots, preinstall their TOCs and payload file paths before fully restarting the game. Publish a serialized data-only packet to all slots via temporary sibling files and atomic rename; avoid trusting a game-reported next-slot value from a stale screen capture. Clear the shared payload global before loading each fresh slot; reject packets whose request/session identity is not pending. Old empty or wrong-request slots are consumed and cannot be reused until UI reload. Publish should be rate-limited and slot polling should back off. Defer loading during combat as a conservative implementation choice, not a claim that all such calls are universally protected.

### Gaps
- No running UI was opened, no game screenshots were taken, and no addon installation was changed during this research.
- A primary Blizzard statement specifically discussing sockets/HTTP/clipboard absence was not located. The absence of a supported direct transport is corroborated by two actual Forever implementations and generated API review, while their workaround claims remain author claims until reproduced.
- Valid murloc 3D creature display IDs and camera settings for the exact client were not verified. Build the mascot with an original asset or test a model before claiming compatibility.
